## Где остановились

Этап 2 закрыт: SQL объяснён, автор согласен с решениями (в т.ч. «удаляется только новая задача» вместо архива). Следующий — этап 3.

- Миграции в `supabase/migrations/` (3 файла: схема → права и RLS → смена статуса), применены в облако `supabase db push --remote`
  (без `--remote` CLI 3.x целится в локальный Docker).
- `pnpm seed` — 3 пользователя (`manager@`, `executor1@`, `executor2@example.com`, пароль `SEED_PASSWORD` в `.env`),
  3 объекта, 7 задач во всех статусах. Скрипт повторяемый: чистит объекты/задачи/историю и создаёт заново.
  Иван видит «Северный» и «Коттедж», Сергей — «Северный» и «Склад».
- `pnpm security-check` — 52/52: атаки падают, снимок базы до/после совпадает, контрольный сценарий проходит.
- Решения по неоднозначностям зафиксированы в `docs/decisions.md` (главное изменение: вместо архива — удаляется только задача в статусе «Новая»).

Факты о базе, которые пригодятся:
- `service_role` по умолчанию тоже получает только `Dxtm` → в миграции ей выданы минимальные права для скриптов.
- Для функций в `public` нет записи default ACL, т.е. по умолчанию `EXECUTE` получает `PUBLIC` → в миграциях
  `revoke execute … from public, anon` и явный `grant` для `authenticated`.
- Имена политик — латиницей: кириллица обрезается по лимиту 63 байта.

Дальше: этап 3 (экраны). Для экранов: ошибки RPC приходят по-русски из `raise exception` — их можно показывать как есть.
