## Где остановились

Этап 3 закрыт: все экраны готовы, сценарии прогнаны в браузере (Playwright + Chrome, локально против облачной базы)
за всех трёх пользователей — 50+ проверок прошли. После прогона демо-данные восстановлены `pnpm seed`,
`pnpm security-check` — 52/52. Следующий — этап 4 (сдача).

Как устроен фронтенд (пригодится для README и созвона):
- `src/api/` — все запросы к базе (TanStack Query): `objects.ts`, `tasks.ts`, `profiles.ts`. Фильтров «по пользователю»
  для видимости нет: что показать, решает RLS. После любой записи — `invalidateQueries()` (перечитать всё).
- `src/lib/status.ts` — названия статусов и копия таблицы переходов, только чтобы показать кнопки. Защищает база.
- `src/lib/errors.ts` — ошибки Postgres по коду → русский текст; `raise exception` из функций показывается как есть.
  `assertChanged`: UPDATE/DELETE, отрезанный RLS, не даёт ошибки, а возвращает 0 строк — проверяем это явно.
- `src/lib/database.types.ts` — типы из схемы (`pnpm gen-types`), клиент `createClient<Database>`.
- Маршруты: `/`, `/objects/new`, `/objects/:id`, `/objects/:id/edit`, `/tasks/new?objectId=`, `/tasks/:id`,
  `/tasks/:id/edit`, `/my-tasks`. Формы создания и редактирования — одна страница на сущность.
